# 0.7.0 — answers to the review of 0.6.0

The review of 0.6.0 raised fourteen findings. This page gives each one its answer, the place in the code and the test that fails without it. **Done** means implemented and tested; **partly** says what is missing.

## Trust in the record

| Finding | Answer | State | Where · test |
|---|---|---|---|
| A stale lock can be removed while its owner still runs | A lock is taken over only when its owner is known to be gone: its process no longer exists on this machine, or its pid now belongs to another process (start time compared), or it was written on another machine longer ago than the limit. A live owner on this machine is never taken over, however old; that is a person's decision (`facet journal unlock`). The takeover moves exactly the judged file aside and gives it back if a new owner arrived in between. An owner releases only a lock that still carries its own token. | done | `lockVerdict`, `takeOver` · `test/fencing.test.mjs` |
| Lock works, fencing is missing | Every forced takeover raises the journal's **epoch**; every event is written under the epoch it was granted. A writer checks just before appending that the lock is still its own and appends nothing otherwise. A process that was paused past all checks and still appends creates a fork: readers settle it by rule — the event under the higher epoch stands, the other is set aside as *fenced*, and `facet journal repair` moves it into `<segment>.fenced`. A fork inside one epoch means the lock was not honoured at all: that is reported as damage. The lock makes forks rare; the epoch makes them harmless. | done | `chain`, `epochOf` · fencing tests, benchmark `journal/fenced-fork`, `journal/unlocked-twin` |
| Digest does not establish authenticity | Digests are now SHA-256 (proof packs, bundles, source state, benchmark). Authenticity comes from **Ed25519 signatures** (`node:crypto`, no dependency): `facet key new`, `facet key trust --role writer|witness|releaser`, trusted keys in the tracked file `.facet/trust.json`. Proof packs are signed when they are created; journal events are signed with `govern.signEvents`. A pack edited and re-digested is TAMPERED (its signature no longer matches); a copied signature is TAMPERED; a key the project does not trust is UNSIGNED; `govern.requireSignature` refuses unsigned packs. | done | `lib/sign.mjs` · `test/v07.test.mjs`, benchmark `proof/authorship` |
| Evidence and manifest are not checked independently | A **witness** re-runs the checks itself on the same sources (`facet proof witness`, or `facet proof verify --rerun`) and compares with what the pack recorded. A witness that gets another answer makes the pack a MISMATCH however intact the journal is; agreement is recorded, signed, and counts in the trust graph. Every evidence of a configured check now carries a receipt: the hash of the command and of its log. | done | `witness`, `witnessed` · benchmark `proof/authorship` |
| Source state misses properties of the file system | Each path is recorded by what a result can depend on: content (SHA-256), the **executable bit**, the **target of a link** (never what it points at), the commit of a **submodule**. The hash cache is reused only when size, mtime, ctime, inode and mode all match and the file is older than the cache by more than the clock's grain. Ignored files a build reads are declared in `govern.inputs` and enter the state. What the state cannot tell apart is listed as `blind` — names that collide on a case- or form-folding file system. | done | `entryOf`, `fileHashes` · benchmark `proof/source-state` |
| The benchmark is tied to a commit but does not describe its environment | Every report records the environment (runtime, platform, tool versions, hashes of lock files, container, CI, locale; names of a short list of variables, never values) and two digests: the **suite** (expectations and fixtures — the exam) and the **result** (suite, answers and the comparable part of the environment). | done | `lib/envinfo.mjs`, `benchmarkReport` |
| Benchmark and proof pack are loosely connected | A proof pack names the benchmark of the tool that made it (`calibration.benchmark`: digest, passed/total) and the guard calibration of the project. `facet proof verify` checks that the benchmark it names is the one this tool ships, and says so when it names none. Packs and evidence carry the environment they were measured in; verification says when the environment differs. | done | `createProof`, `verifyProof` |

## Withholding and experiments

| Finding | Answer | State |
|---|---|---|
| "Safe" withholding is not really safe by default | Withholding stays off by default. When it is on, it is **per item, not per step**, at most one rule per item, drawn once when the item opens and recorded on `item.open` with its probability. Only rules marked `ablatable: live` qualify, and only while every one of their **backstops** — the check a tool enforces when the rule is absent — is required by the project's policy at the level it demands. | done |
| 60 facets had no explicit `ablatable: no` and could be withheld | Every facet now says what it allows: **no** (16 — never, not even in a replay), **replay** (33 — only in a counterfactual replay of finished work), **live** (20 — also in real work, with a backstop). A facet that says nothing is treated as `no`, and `facet audit` fails it. | done |
| The unit of an experiment can bias the result | The unit is the **item**: every step of one item gets the same arm (a later step looks up the arm the item was dealt), and the analysis collapses steps of one item into one observation before comparing arms. Counterfactual replays (`facet cf`) are paired — with and without the rule from the same snapshot — and judged by a sign test, so the task, the code and the difficulty are held equal by construction. | done |

## Orchestration and process

| Finding | Answer | State |
|---|---|---|
| Adaptive orchestration is ownership, not adaptation | The route now changes **while the item runs**, by rules, each change an event with its reason: the files changed so far are planned again and add the agents and gates the opening plan did not see (`grow`); an agent sent back for the same cause at least three times on this project gets the rules that guard that cause (`reinforce`); an agent whose record on its model is weak beyond doubt runs one model up (`escalate`). Adapting never removes a step, drops a gate or lowers a model. | done — v1; cost-aware routing and learned skipping are in the 2.0 plan |
| Facetkit is hard to understand; no visible results for different people | `facet explain --for dev|lead|client|auditor [--html FILE]` tells the same record to the person who acts on it: the next command; where rework and tokens go; what is done and how sure we are, in words; every rule, exception and signature. `docs/how-it-works.md` explains the system by role, with one example each. | done |

## What 0.7.0 does not do

- A signature makes a record attributable, not true. A key that leaks signs anything; rotate it with `facet key trust` and a commit that removes the old one.
- The lock still depends on exclusive create. Network and synchronised folders that do not honour it produce forks; fencing makes them harmless only when an epoch separates the writers. Give each machine its own `FACET_WRITER` there.
- A witness on the same machine shares its environment with the original run; for independence of environment, run the witness in CI or on another machine (the environment of each run is recorded so this can be seen).
- Adaptive orchestration learns from this project's record only. With fewer than five observations it changes nothing.
