# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- **The source state of an event is written as `state`** (it was `src`). Since 2.3, `src` on an imported event is the line of a domain journal it came from (`{ journal, n, hash }`, as the plan names it); on evidence the two meanings would have collided, and every imported result would have counted as measured on other sources. Events written before keep `src` as a string and are read by that rule (`stateOf` in `lib/journal.mjs`); nothing is rewritten. The proof pack format is unchanged.

### Added
- **The echo in the domains** (plan 2.9, domain engines). arch-flow and viz-flow get `echo check <step>` (`echo_check.py`, the same rules as the core's), and `end <step> --status DONE` refuses a step that owns criteria of the approved block without a passing echo. Two failures in a row print BRIEF NOT READABLE and write `echo.return`; `facet domain import` turns it into an `origin` against the brief. `echo` events come over as core `echo` events. The producing agents of both domains write the echo first.
- **The echo of understanding** (plan 2.9, core). Before its first working action, the agent of a step that owns criteria writes `echo.json`: each criterion's value as the brief states it, the action, the check, the Fixed lines and what it does not know. `facet echo check <step>` measures U1 (every criterion of the step), U2 (numbers with units, quoted words and identifiers as written — `20 cm` for `25 cm` is refused), U3 (every Fixed line) and U4 (criteria the brief does not have: a question, not a refusal). `flow end` refuses a step that owns criteria and has no passing echo. Two failures in a row send the brief back, recorded against the brief (`origin`, cause `brief-unreadable`). The producing agents write the echo first. The board shows U6–U8.
- **Criteria and their source in the domains** (plan 2.8, domain adapters). arch-flow 0.3.5 and viz-flow 0.4.5 accept a `criteria` block in the brief's Acceptance, held to the same gate as the core's. `[look: …]` counts as judged by a person, like `[user]` (the owner's decision of 22.11), and at most three such criteria are allowed — in the block and in the numbered lines. `brief approve` records the list and its hash, which equals the core's `criteriaHash`. `facet domain import` turns that record into the item's `criterion` event. Both `domain.json` files declare `chains`: links with the step that produces each, and how each pair is compared. In arch, `spec>model` is compared by `spec_compare.py` (exit 0 the same, 1 differs, 2 cannot say); a drawing or task read by eye is `human`. In viz, no tool compares the links yet. `facet origin` on a domain item follows that chain; commands name `{python}`, `{scripts}`, `{work}`, `{item}` and `{criterion}`.
- **The source step of a finding** (plan 2.8, steps 3–6). `facet origin --criterion A3 --from return|human|defect` — and `facet flow verdict REWORK … --criterion A3` on its own — records an `origin` event. A criterion not in the brief goes to the brief, and nobody who worked is charged. Otherwise the first differing pair on the criterion's `chain` is the source (`chain`). Otherwise the criterion's check is run on the snapshots after each step from `by` to where the problem was found: never met → `not-done`; broken later → bisection finds the step (`measured`). Else it is the step the reviewer names (`judged`). The trust graph charges from origin events: the source 1, each judge in between 0.5, a false green, or the tool for `--tool-defect`. The board shows K1–K5.
- **Numbered acceptance criteria** (plan 2.8, step 1). A `criteria` block in the brief (the order handoff in the core) lists each criterion with `id`, `text`, `check` (a registered tool with a threshold, or `[user]`), `by` (the step that must make it true) and an optional `chain`. The gate refuses a criterion without a check and more than three `[user]`; `flow end` applies it to any handoff that carries the block. `facet criteria approve --by <person>` records the list and its hash (a `criterion` event); `facet criteria check` says when the brief no longer is the approved list; `facet criteria list` shows it.
- **Domain journals into the core one** (plan 2.3, first part): `facet domain import <journal.jsonl> --domain arch|viz [--anchor n:hash] [--prefix X] [--dry-run]`. The chain of the arch-flow or viz-flow journal is checked first — the hash is recomputed over the line exactly as Python wrote it, Python's number text included, and lines of versions before 0.3.2 at their 16 characters; an edited, removed, reordered or torn line stops the import with its number, and nothing is written. An `ANCHOR` the domain printed at a close must still match. Each line becomes one core event pointing back to it (`src: { journal, n, hash }`); open, steps, evidence with its receipt, waivers, verdict, close, signed lists and acceptance become their core kinds, the rest `domain.<type>`. A second import adds only new lines. An imported item has the steps of its domain route — from `routes.json` beside the journal (or `--routes`), else the steps it started — with the inspector's step as the one that judges, so the core sees who worked and who gave the verdict.
- **A domain item is proven on its declared artifacts** (plan 2.3). `facet proof create --item X --domain arch|viz [--domain-root DIR]` binds the pack to the files the domain declares — `artifacts` in `domain.json`, globs relative to the domain root with `<ITEM>` for the item's id there (both domains ship `work/<ITEM>/**`; a `domain.json` beside the project's domain journal wins) — instead of the git tree. The files are read from disk whether git tracks them or not; the declaration is part of the hashed state; a pattern that matches no file is a blind spot; `proof verify` checks against the declaration the pack carries. The domain root is the folder of the journal the item was imported from; a pattern or a root that would leave the project is refused. An item imported with `--prefix` keeps its domain id (`domainItem`), which names its folder.
- **A witness in CI** (plan 2.4). `facet proof witness --pack FILE` witnesses a pack named by its file and `--out FILE` writes the witnessed copy elsewhere, so the pack a pull request carries stays as it is; `--record FILE` writes the signed record alone, for an artifact or a comment. `--key-env NAME` signs with a private key held in that variable (a CI secret, PEM text) and keeps it out of every command run; `FACET_WITNESS_KEY` is never passed to a command, whatever `govern.env` says. A check in `govern.checks` may say what it needs (`"requires": ["archicad"]`): a witness without it does not run that check (`--with archicad,blender` on a machine that has them), and a record that could not run every check vouches for nothing. A `proof.witness` event records the level the record could vouch at; the board shows the share of packs an independent witness reproduced. The workflow itself comes separately (a guard file).

## [0.7.1] — 2026-11-22

The first item of the plan to 1.0 — close what was obviously open — done as the plan says: a threat model, CI on three systems with Windows required, journal schema 2, required event signatures, signed and levelled witnesses, a scanner that says what it did not read, commands without the process environment, SHA-256 throughout, and trust read from a commit. Besides the plan: a GitHub Action (`facet ci-verify`), guides for new users, `facet init --agents` and `--github`, and the domains arch-flow 0.3.4 and viz-flow 0.4.4. **Read before updating:** commands now get only ten environment variables (name the others in `govern.env`); `govern.signEvents` takes `"off"`, `"on"` or `"required"`; trust is read from the committed `.facet/trust.json`; an item whose change the scan could not read does not close until each file is approved with a reason.

### Security
- **L4 needs trust from a commit** (plan 2.5, guard part). When `.facet/trust.json` is read outside git (trust marked *uncommitted*), nobody can check who added the witness's key: a proof stands at L3 even with an independent witness, and `proof verify` says why. In git nothing changes.
- **Trust comes from a commit** (plan 2.5). `.facet/trust.json` is read as committed at `HEAD`, or at `govern.trustRef` (for example the reviewed `origin/main`); a key added to the working copy and not committed is not trusted, a key removed and not committed still is, and every run that reads trust names the difference on stderr. `facet key trust` says the key counts once committed. Outside git the file is read as it is and marked *uncommitted*; an unreadable file is an error, not an empty list.
- **No SHA-1 left in governance.** The hash of a policy (which a proof compares with the verifier's own policy) was 12 characters of SHA-1 — a weaker policy with the same 48 bits could be searched for — and an attestation's digest 16. Both are now SHA-256 over canonical JSON. A proof made before 0.7.1 is read as **legacy**: its 12-character SHA-1 policy hash is checked by the old rule, and `facet proof verify` marks it legacy and says that `facet proof create` makes a current one. An attestation written before is likewise checked by its own rule.
- **Commands get part of the environment, not all of it.** Checks, witness runs, decision measures, bug reproductions, `facet run`, `facet eval judge` and the test command of `facet mutate` used to inherit every variable of the process — tokens and cloud credentials included. They now get `BASE_ENV` — `PATH`, `HOME`, `USERPROFILE`, `TEMP`, `TMP`, `LANG`, `SYSTEMROOT`, `COMSPEC`, `PATHEXT`, `TERM` — and what `govern.env` names (a list of names, or prefixes ending in `*`; on Windows without case). **This can change behaviour:** a check that needs any other variable (a toolchain home such as `JAVA_HOME`, a proxy, `NODE_OPTIONS`, `TMPDIR`, a registry token) must have it named in `govern.env` — on Windows Go needs `LOCALAPPDATA` (or `GOCACHE`) and npm `APPDATA`. There is no way to pass everything: `govern.env` that is not a list is an error. `FACET_KEY` and `FACET_KEYS` are never passed.
- **The allow-secret marker no longer hides a secret.** A line with the marker was taken out of the search, so anyone could hide a real key by writing the marker after it. The marker now counts only in a path the policy ignores (`govern.scanIgnore`), which is not searched at all; anywhere else it is a blocking `allow-outside-ignore` finding with its line number, and the line is searched like any other.
- **What the scan did not read is said.** A changed file larger than the limit (400 000 bytes) or binary used to be passed over in silence, so a secret in it went unseen and the scan still read clean. Now it is a `not-scanned` finding with its reason that needs a person's approval (`facet approve not-scanned:<file>`), the scan is `partial`, and the L1 rule `approvals` fails until it is approved. Whatever level a project requires, `facet flow close` refuses while such a file is not taken off by an approval with a reason (`--note`, required for these approvals). `facet scan` prints PARTIAL and exits 2 (1 is still "something blocks"). Special files (devices, sockets) among the changes are no longer opened.
- **Two levels of witness.** A witness record now says on which machine it ran (a hash of the host name, added to the environment record) as well as in which environment. A trusted record from another machine and environment is `independent`; one from the same machine is a `rerun` — repeatability, not independence. A record or a pack that does not say where it ran is a rerun. A pack whose journal gives L4 stands at L4 only with an independent witness; otherwise `facet proof verify` reports L3 and says why (`claimedLevel` keeps what the journal gives).
- **Signed events can be required.** `govern.signEvents: "required"`: every schema-2 event must be signed by a key the project trusts; an unsigned event, or one signed by a key the project does not trust, makes the journal `tampered` — taking signatures off and keeping the chain whole no longer passes. A process without a key writes nothing rather than an unsigned event. `govern.signEvents` takes `"off"` (the default), `"on"` (sign when a key is at hand) or `"required"`; any other value is an error. `facet journal` prints the number of such events on a line of its own. Older-format events are not asked for signatures.
- **A witness record must be signed to vouch.** The list of witnesses lies outside a pack's digest, and any record in it counted as an independent reproduction — one could be written in by hand. Now an agreeing record counts only when its signature (over the canonical record) is by a key the project trusts in the `witness` role, and not by a key that signed the pack: the author re-running its own checks is repeatability, not a second opinion. A disagreeing record counts by the same rule: a record that cannot vouch is listed with its reason and changes nothing, either way. `facet proof verify` says which records do not count and why; `facet proof witness` refuses to run without a key trusted in the `witness` role. Records signed before this change (over non-canonical JSON) no longer count.
- **Journal schema 2.** An event's id is the full SHA-256 of its canonical JSON (`lib/canon.mjs`) without id and signature, and `prev` is the id of the event before it — so a signature over the id covers the event, its place in the chain, its writer, number and epoch. Before, ids were 12 and links 8 characters of SHA-1 (48 and 32 bits). The chain recomputes each schema-2 id, so an edited event is found at its own line, also where only the chain is checked (proof bundles). Events written before are read and continued by their own rules and never rewritten; `verifyJournal` counts them as `legacy`. After a schema-2 event, an older-format event or an unknown schema breaks the chain, so a 32-bit link cannot be brought back by appending one line.
- `SECURITY.md` states the threat model: four sources of harm (an agent that errs, an agent that games the record, foreign content, accidents) and what is out of scope (whoever controls the machine or the repository); a table says, for each guarantee, what it rests on and when it does not hold. `facet audit`, run on this repository, fails when the threat model is missing or incomplete; a test keeps both sections present and complete.

### Fixed
- `facet` did not start at all after the first version of `ci-verify` (a second declaration of `command`, and the command placed inside `ui`): every test and the nightly run failed. The first `action.yml` called `bin/facet.js`, which does not exist, put its inputs straight into the shell script (a branch name or PR title passed as an input could run as code), and the PR comment went to `https://github.com{repo}` instead of the API; a fork's read-only token made the whole run fail. Fixed, with tests.
- The READMEs no longer state numbers by hand: tests, benchmark cases and untested hypotheses are counted from their sources by `npm run counts` and written between `<!-- count:… -->` markers; `facet audit`, run on this repository, fails when they differ, and so does a test in CI (the README said 185 tests when there were 241). The Polish README states them in a form whose grammar does not depend on the number.
- Journal after a Windows checkout: git's `core.autocrlf` adds a CR before every LF, and an older-format link is a hash of the line's bytes, so an untouched journal read as tampered. The reader takes one CR off the end of each line before hashing — restoring the bytes facet wrote — and forgives nothing else: an edit is still found.
- Checks, witness runs, decision measures and bug reproductions run through the platform's own shell (`lib/shell.mjs`, `runCommand`: /bin/sh, or cmd.exe on Windows) instead of `sh -c`, which Windows does not have. A timeout stops the whole process tree, and facet stops the trees it started when it is interrupted.
- `{item}` in a configured command is filled only with an id of letters, digits, `.`, `_` and `-`; any other id is refused, and `FACET_ITEM` is set only to such an id — a shell must not read an item id as more than a name.
- Step snapshots give back the exact bytes they took on Windows (git's line-ending conversion is off for them).
- Extensions listed by an absolute path load on Windows.
- `.gitattributes` keeps LF in text files: hashed files no longer change on a Windows checkout.
- `npm test` works on Windows with Node 20: the test files are listed by `scripts/test.mjs` (cmd.exe and Node 20 expand no `*` pattern).
- CI runs on Linux, macOS and Windows × Node 20 and 22, and every one of them must pass.
- Journal lock on Windows: `EPERM` while another process deletes the lock file is contention, not a failure — the writer waits as it does on `EEXIST`; removing the lock retries while another process is reading it. A real permission error is still raised once the wait is over.
- Benchmark `proof/source-state` on Windows: where a file system has no executable bit, or symbolic links need a privilege the process lacks, the case passes by the rule's own terms (nothing there can change unnoticed), as it already did for case-folding names. Where the property exists it is measured as before; `benchmark/expected.json` is unchanged.
- Adaptive routes: a step the plan asks for before a step that has **already started** no longer goes in front of it (which reset the started work); it goes after it in `REVIEW` mode and reviews that work.
- Adaptive routes escalate a step's model only when most of that agent's reworks had a capability cause (`false-green`, `seam-break`, `spec-gap`, `regression`, `weakened-test`, `lost-work`, `loop`, `repeated-mistake`). Reworks for handoffs and documents are answered by reinforced rules, not by a model five times the price.
- A step ended `DONE` with `--force` over a failed handoff check is still no failed rule, but it is no longer invisible: `facet assure` lists each such step with its `--reason`, and `facet trust` counts them next to forced steps.
- `facet flow end` no longer asks a step to list changed files that another handoff of the item already lists or that belong to another agent's territory. With a team rule "never list another agent's files", every step that ran after another agent's changes could only end with `--force`. The manifest is `owners`, `owners.json`, or `territories` — a team file of agent → paths.

### Added
- **Three guides for new users**, in English and Polish: [quick start](docs/quick-start.md) (ten minutes on your own code, no agents), [project integration](docs/project-integration.md) (one rule for your own agent, or only the agents you choose) and [GitHub integration](docs/github-integration.md); linked from the top of both READMEs.
- **`facet init --agents a,b`** builds the flow from the chosen agents only, in the order of the default flow, and with `--claude` copies just those agents. Without `proof-inspector` nothing judges the work: `govern.required` is set to 0 and `init` says that items close at L0.
- **`facet init --github`** writes `.github/workflows/facetkit.yml`: the Action on pull requests, full history, the comment permission, the toolchain of the project (Node, Python, Go, Java from the files it has) and the Action pinned to this release. Alone it writes nothing else.
- Action inputs `max-mutants` and `max-minutes` (both 10 by default) bound the mutation probe; `facet ci-verify --max` and `--max-minutes` refuse anything but a whole number of at least 1.
- A change without source code (documentation, configuration, a workflow) shows the mutation probe as **not needed** instead of *not run*, with the reason.
- **GitHub Action and `facet ci-verify`.** `uses: Anctoster/facetkit@<ref>` in a workflow scans the change, runs the tests and probes the changed lines with mutants, and writes one PR comment that every run updates, a job summary, `level` and `passed` outputs and `facetkit-report.json`. Without a journal entry for the item (*stateless*): L1 a clean scan, L2 the tests pass, L3 at least 80 % of the mutants of the changed code are noticed — a level of this run only, not a proof pack. With the item in the project journal, the level comes from the journal after `facet journal` and `facet proof verify` have checked it. The item id comes from `--item`, the branch name, the PR title or the PR number; the change starts at the merge base with the PR's target (a shallow checkout is an error that says to use `fetch-depth: 0`, not an empty change).
- The first field report, `trials/field/field-1.json`: what nine closed items of one web application's roadmap say about 37 facets (exposure, adherence, effect, verdict), anonymous — no project name, file names, commands or text. `facet hypotheses --next` ranks by it.

- **Testers** (`facetkit/qa`, `facet qa`): `plan` — a risk map of what changed (class, dependents, whether a test reaches it, churn, escaped defects) with the tests each area calls for; `charter new|close|list` — time-boxed exploratory sessions; `bug new|verify|confirm|list|close` — bugs that carry their reproduction, run several times (reproduced, not reproduced, flaky), confirmed by a second person when they are steps, fixed only when the reproduction passes and `verified` only with a test that names the bug; `readiness` — GO/NO-GO with every reason. A bug reported with `--item` in closed work is recorded as that item's escape.
- **Plugin `qa-flow`** (`domains/qa`): test-strategist, exploratory-tester, bug-verifier, release-judge and the `/qa-item` skill.
- **Architecture decisions with measured predictions** (`facetkit/decisions`, `facet decide new|check|list`): a decision record carries fitness rules or commands that must keep holding; a failed measure sends it to review. Records in `docs/decisions/` as JSON and Markdown.
- `facet explain --for client --lang en|pl|ru`.
- **Agent efficiency for building architects** (`arch-flow`, `viz-flow`): `hand ITEM --hours H` — the architect's estimate of the hand work, taken before the agents start (a later one is shown, not used); `spent ITEM --minutes M --on brief|questions|preview|review|fix` — the architect's own time; `efficiency [--route] [--lang en|pl|ru] [--html] [--json]` — per task type: right the first time, accepted as delivered (80 % intervals), time saved against the hand work, agents' time, tokens and cost, questions and preview rounds, what the checks caught, which agent on which model is sent back and whether a cheaper model does as well, and a verdict that refuses to conclude from fewer than five items.
- Docs: `docs/for-testers.md`, `docs/for-architects.md`; `how-it-works.md`, `governance.md` (signatures, witnesses, statuses), `skill-intelligence.md` (withholding modes, per-item units, counterfactual replay), `architecture.md` (fencing), `SECURITY.md` (keys) brought up to date.

### Security and trust — domains (`arch-flow` 0.3.1, `viz-flow` 0.4.1), after the audit of 16 November
- **Receipts.** Every tool stamps its results file with the hash of its own code and inputs (`receipt.py`); `evidence --from` takes a file only when that hash is the tool shipped next to the journal or a registered script. An OK can no longer be recorded by hand; a finding by hand needs `--reason`. `img_digest.py --results` and `diff --out` write the evidence for `images` and `invariants`.
- **Script registry.** `script register|drop|list|lock`: the operator role runs a mode only when its script is registered in the journal by hash; a path in `project.json` is not a registration. A transaction that ran an unregistered or edited script is refused as evidence outside the builder's own item. `txn.py` takes the operation's text as a parameter only from the self-test.
- **Ids and paths.** Item ids are `[A-Za-z0-9_-]{1,64}`; `trace.py` evidence cannot point outside the delivered folder; `asset_paths` resolves links.
- **`ifc_read.py`** gives every element its position, direction and a fingerprint of its representation, converts lengths to metres from the file's unit, keeps elements of classes it has no special reading for as `other`, counts records it could not read, and refuses schemas other than IFC2x3 / IFC4.
- **`change.complete`, `bim.complete`** (required on `revise`, `change`, `audit`, `rules`): "identical" and "audited" are said only when positions, sizes and all records were there to compare.
- CI runs the domain tests on Windows as well; a test keeps the two journal engines one text.

### Trust, second round — domains (`arch-flow` 0.3.2, `viz-flow` 0.4.2)
- **Journal.** Full SHA-256 in the chain (lines of earlier versions verify at their own length and are never rewritten); `anchor` and an ANCHOR line at every close, `verify --anchor n:hash` — the chain alone can be recomputed, an anchor kept outside the folder cannot. Lock by owner (pid and host): taken over only when the owner is gone, never by age; `fsync` on every line; project files written atomically.
- **Release gate.** Proofs sent back by `stale` are remembered; routes named under `release` (`issue`, `pack`) refuse to open or pass until each is re-run in an item that passed, or waived by name (`stale status`, `stale waive`).
- **Decisions in a person's name.** `sign <file> --by` pins a list by hash; results of `rules_check.py` and `trace.py` are taken only against a signed, unchanged list. `approvals` and every close list what was approved, signed, waived, forced and registered, for the requester to recognise.
- **Foreign text** (`safe.py`): cleaned and cut wherever a tool prints it; text that addresses its reader (en, ru, pl) is counted in the IFC census, fails `bim.complete` / `trace.clauses`, and is shown as a question. Agents treat sources as data.
- **`trace.py`**: search expressions must hold a word of four letters, are length-limited, and nested repeats are refused; the matched row is reported; one row answering several clauses is named.
- **`outbox_check.py`**: `outbox.read` (scanned pages, oversized archives are "not read", required on `issue`), tracked changes, hidden text and sheets, headers and footers, `outbox.metadata`; archive size limits.
- **Exit codes** of all tools: 0 passed, 1 failed, 2 nothing failed but something was not checked.

### Trust, third round — domains (`arch-flow` 0.3.3, `viz-flow` 0.4.3)
- **What a result covers** follows from what it claims: model-wide results (`bim.*`, `rules.*`, `spec_compare`) cover `model` and are sent back by any model change, a new story included; claims about one pair of snapshots (`change.*`) cover only that revision; a sheet without `shows`, and every sheet when an element on no story changes, count as touched; `stale` reads `story:` / `zone:` as a change of the model. `swap_check.py` touches the zones of every object that differs in anything, allowed or not, and the whole scene for an object without zones.
- **`swap_check.py --min-match`** (default 95 %): below that share of the old model's objects found again (outside `--allow`), `swap.kept` is SKIP, never OK; matches by name only are reported.
- **`img_compare.py`** reports how fine its sieve was (cell size, the smallest full-contrast detail that can stay below the threshold, the largest difference outside the expected cells) and fails on a change of brightness of the cells not expected to change (`--max-shift`); its OK says it narrows where to look and does not prove sameness.
- **Lessons are proposed until a person confirms them** (`memory confirm`, `memory proposed`); recall shows confirmed ones only; text that addresses its reader or carries control characters is refused; `close` lists the item's proposed lessons. Lessons written before this version count as proposed.
- `safe.py` is shared by both plugins and kept one text by a test.
- The domains' efficiency report (`hand`, `spent`, `efficiency`; see Added) is kept in 0.3.3 / 0.4.3: the third round was built beside it and both are merged here.

### Fixed — domains (`arch-flow` 0.3.4, `viz-flow` 0.4.4)
- **Journal lock on Windows.** With many sessions writing at once, Windows answers *permission denied* — not *file exists* — while another session is deleting its lock, and refuses to delete a lock that another session is reading to see whose it is. Either made a command fail although its event could be (or had been) written. Both are now waited out; a lock that still cannot be removed after two seconds is left for the next writer, which takes it over once its owner has ended. Found by the 16-writer test on the Windows CI runner.

### Not done, on purpose — domains
- No clash detection (a snapshot holds no geometry; Archicad's own collision detection stays the source) and no insolation.
- No regulation is shipped: `rules.example.json` is a format with placeholder numbers.
- No vision model is called by a tool: what the scene can answer is measured in the scene, pictures are compared by numbers, and the inspector looks only at the cells that differ.

## [0.6.0] — 2026-11-15

- **arch domain 0.2.0 — variant sketching before the drawing sets.** Route `variants` (site plan, layouts, facades, in that order): an agent proposes three to five different ideas with geometry; `variants.py` derives the indicators, tests the architect's limits, refuses near-identical variants, scores by the architect's weights and names variants beaten on every criterion. A variant over a limit is shown and marked, never dropped; the choice is a person's gate. Plan `design` lays out a commission from the first sketch to both drawing sets.

### Added
- **Journal writer protocol.** Appends run under one lock per journal (exclusive-create lock file with owner, takeover of a dead owner's lock, a bounded wait). `verifyJournal` now checks structure as well as the hash chain — sequence numbers, the logical clock, the writer of each segment, lines cut off mid-write — and answers with a single `intact`. `facet journal repair` sets a torn tail aside in `<segment>.torn`; nothing is repaired silently.
- **Proof packs** (`facet proof create|verify|status`, `facetkit/proof`): one manifest per item tying its rules and evidence to a source state — a hash over the content of the working tree, unchanged by a commit of the same content, changed by any edit. Verification answers VALID, STALE, TAMPERED, MISMATCH or UNKNOWN and is reproducible on another clone.
- **Source-bound evidence.** Every evidence event records the source state it was measured on; evidence from another state is stale (conservative invalidation). `govern.source: "off"` restores time-only staleness; `govern.sourceIgnore` lists paths that are not sources.
- **Experiments** (`facet experiment new|start|stop|report|arm`, `facetkit/experiments`): manifests in `trials/experiments/`, seeded assignment recorded on `step.start`, held-equal model and task class, Wilson intervals with a Bonferroni correction, and exploratory → confirmatory → validated stages.
- **Facet Intelligence Engine** (`facet intel design|start|stop|report|size`, `lib/intelligence.mjs`): multi-arm designs (facet off / on / candidate wording / another model / another position), permuted-block assignment inside strata of role, task class and difficulty, six outcomes read from the journal (clean close, errors, false passes, retries, tokens, minutes), a seeded stratified permutation test with bootstrap intervals, Holm correction, a floor of 30 units per arm and `intel size` for the planned number. Measured on simulated journals: 5 false alarms in 100 experiments where the facet does nothing; a halved failure rate found in 76 of 100 at 75 units per arm and in 22 of 100 at 30.
- **Skill evolution** (`facet evolve scan|list|test|adopt|reject`, `lib/evolve.mjs`): recurring causes → the guarding facet → delivered? followed? → one of six diagnoses (create, load, instrument, reword, change, to-tool) → a proposal → an experiment → adoption only on a confirmed, favourable result and only with `--by`.
- **Route planner** (`facet route`, `lib/planner.mjs`): file classes, dependents from the import graph, owners and their order of work, a risk score with reasons, optional agents chosen by risk, skippable steps for pure documentation or style, and locked security gates. On seven scenarios: fixed route 79 agent calls with 8 unneeded; by file class only 52 calls with 1 required agent missed; adaptive 54 calls, none missed, none unneeded.
- **Trust decay** (`facet proof decay`, `facet check --stale`): per-check scopes (`covers` plus import closure), evidence bound to its scope digest, per-state snapshots, blind spots named.
- **Hypotheses** (`facet hypo`), **lessons** — cognitive memory and learning (`facet learn`), **trust graph** (`facet trustgraph`), **self-healing** (`facet heal scan|apply|undo`) and the **capability economy** (`facet economy`): see `docs/cognitive.md`. Lessons recalled for a step change the rules it is given; a weak agent can be put on probation one model up; a contradicted check stops counting.
- **Portable proof bundles** (`facet proof export`, `facet proof verify --bundle FILE [--root DIR]`): the pack, the journal it rests on and the policy in one sealed file, verified with nothing else — VALID, STALE, TAMPERED or MISMATCH, step by step. `npm run demo:proof` plays the whole scenario and runs in CI.
- **Identity**: events carry an id (the hash of their content), and a session and actor when `FACET_SESSION` / `FACET_ACTOR` are set; steps record their run (`--run`, `FACET_RUN`). The judge is independent only if it is another agent *and* another run; with `identity: "required"` a missing run id is unknown. `verifyJournal` answers with a status: empty, intact, torn, tampered, malformed, conflict.
- **Mutation outcomes** are five and never merged: detected, survived, equivalent (declared in a manifest), invalid (the mutant does not load), not executed. A nightly workflow probes the guard files.
- **Benchmark** reports have a schema and a trend across versions (`facet benchmark --trend`); CI stores each run as an artifact with commit and Node version.
- `ROADMAP.md`, `ARCHITECTURE.md`, `GOOD_FIRST_ISSUES.md`, `.github/CODEOWNERS` and a guard-file rule in `CONTRIBUTING.md`; the memory store appends under the journal's lock; designs can be stratified by model and risk (`--strata`).
- **Ownership** (`facet owners`, `facetkit/ownership`): most-specific-pattern resolution, with unowned files, equal claims and foreign edits refused.
- **Guard benchmark** (`facet benchmark [--write]`, `facetkit/benchmark`): adversarial fixtures under `benchmark/fixtures`, expectations in `benchmark/expected.json`, results per version in `benchmark/results/`, regressions named.
- **`domains/arch`** — the method for architectural production in Archicad, as a third plugin (`arch-flow`): task cards, a checked building description read once from texts and raster drawings, model-against-description comparison, drawing-set checks for two stages, and a schedule simulation that reports dates, the chance of missing the deadline and the gain of each measure. The journal engine of the domains is now one file configured by a `domain.json`.
- **`domains/viz`** — the method applied to architectural visualization, as a second plugin (`viz-flow`) in the marketplace. For large scenes: an object index instead of the scene, zones so that cost follows the change, and headless copy-on-write transactions that commit only what an operation declared (`domains/viz/skills/viz-item/scripts/COMPLEX.md`).

### Changed
- **Governance is fail-closed.** `journalIntact` is unknown unless the caller established it, and unknown does not pass (`evaluate` marks such rules `unknown`). Library callers that evaluated in-memory events must now pass `project: { journalIntact: true }` after verifying the journal; `facet` does so itself.
- A waiver no longer opens the gate for an unknown rule; it still never raises the level.
- `readJournal` skips a line that is not an event instead of throwing; `verifyJournal` reports it and `record` refuses to append after it.
- An absent journal is not an intact one: `verifyJournal(...).intact` is false when nothing was recorded.

### Fixed
- Two processes appending at once could take the same sequence number and logical clock, and a reader could meet a half-written line and crash. Measured on 0.5.1 with 20 writers × 100 events: 1910 of 2000 events survived, one writer crashed, 525 events shared a clock value. On 0.6.0: 2000 of 2000, intact.
