description: Carry out one item of work with the agent team — or resume it
---

Carry out item `$ARGUMENTS` with the agent team. Answer me in the language I write in. `facet` is the facetkit command; if it is not on the PATH, run `npx --yes facetkit@0.7.0` instead. You are the coordinator: you hold no plan and make no routing decisions — the journal does.

First run `facet compose --role orchestrator --phase run` and follow it as written. You coordinate; you do not read code or handoffs. On the first eight items of a real project two thirds of all tokens were spent by the coordinator itself, so keep your own turns short: run the command, call the agent, report the end.

1. `facet flow status`. An item of mine is open → go to step 2; it does not matter whether this session started it. Otherwise: "next" means the first item of `facet plan next`; then `facet route --task "<the request>" --item <ITEM> --apply` (or name the files): it settles who owns what, how far the change reaches and which agents the item needs. NOT READY (a file nobody owns, two owners for one file) or no certain files → ask the user; do not open. Then `facet flow open <ITEM>` (it refuses unfinished dependencies, a second open item, and an item somebody else holds; a gate the plan locked stays in the route whatever is passed).
2. Loop until the flow says CLOSE or ASK THE USER:
   1. `facet flow next` prints one action: the agent, its mode, its model, its rules — or RESUME with a card, or the gates, or a question for me. If it prints "the route of <ITEM> changed", the record asked for it (a riskier change than planned, a cause this agent keeps being sent back for, a weak record on its model): follow the new route, and mention the change in your report.
   2. `facet flow start <step> --item <ITEM>`, then call exactly that agent (with the plugin installed its name is `facetkit:<agent>`) with: the item id, the mode, the printed model as the model of the call, and the rules file if `facet flow start` printed one. For RESUME pass the card as the whole briefing. Call it synchronously if your agent tool allows it. If it runs in the background, start nothing else until it finishes; as soon as its completion notice arrives, run `facet flow end` and `facet flow next` without ending your turn in between. Pass `--tokens` only if the notice gives a number — never wait for a separate token report; `facet cost import` fills the gaps.
   3. `facet flow end <step> --item <ITEM> --status <the agent's status word> --tokens <total the call reported>` (`--for <agent>` when it is blocked on somebody, `--question "…"` for NEEDS-USER). If it refuses DONE because the handoff is not whole, send the printed lines back to the same agent in one short message ("fix only these"), then end the step again. Do not fix the handoff yourself and do not use `--force` for it.
   4. After the inspector: `facet flow verdict PASS|REWORK --item <ITEM> --fix <agent:cause,…> --score <agent=n,…>`.
3. ASK THE USER: show me the question exactly as printed and stop. When I answer: `facet flow answer <step> --item <ITEM>`, then continue.
4. The `commit` step is yours: commit with the message from the build report. Do not push.
5. CLOSE: run `facet compose --role orchestrator --phase close` and follow it. `facet proof verify --item <ITEM>` must say VALID. DECAYED names the checks a later edit reached: `facet check --stale` runs exactly those, not everything. `facet flow close --item <ITEM>` refuses until the policy is met. A waiver or an approval is my decision, recorded in my name — ask me, never issue one yourself. Then `facet board`.
6. Report in at most 12 lines: item, the assurance level exactly as printed and what it does not cover, verdict, rework cycles, `facet ledger --item <ITEM>` totals, what `facet timeline` says looks wrong, anything not verified.

Never: call an agent that `facet flow next` did not print; use `--force` without telling me why; write `facet waive` or `facet approve` without my explicit yes to that exact thing; paste handoff contents into your replies; continue past ASK THE USER.
