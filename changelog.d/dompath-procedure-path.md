### Changed
- **A builder naming its procedure is not a change of the checks** (arch-flow 0.3.6, viz-flow 0.4.6). The builders are told to write the path of a new procedure into `project.json` → `scripts`, and `project.json` is a check file of H2, so every first run of a mode stopped at `approve-checks`. `checkKeysIgnored` in `domain.json` leaves that one key out of the H2 hash: the path is a proposal, and the journal's registry by hash guards what runs. Every other key of `project.json` stays guarded. This makes a guard pass more often, so it is a security change: the tests show that a threshold changed together with the path is still caught.
