# viz-flow

Метод и команда агентов для подготовки графики сайта продаж: Archicad → Blender → рендеры → изображения для сайта. Построен по схеме facetkit (github.com/Anctoster/facetkit, MIT), перенесённой с программного кода на сцены и изображения.

## Как это работает

1. Задача открывается как «изделие» на одном из маршрутов. Новый проект целиком раскладывается командой `plan new-project`, цикл после изменения модели — `plan model-change`.
2. Первый шаг каждого изделия — **бриф**: что должно получиться, что нельзя менять, и до 9 критериев приёмки. Каждый критерий помечен: `[check]` измеряет скрипт, `[look]` смотрит инспектор на одном листе кадров, `[user]` решаете вы. Расплывчатый бриф инструмент не принимает. Вы утверждаете бриф один раз, до начала работы.
3. Журнал (`_viz/journal.jsonl` в папке проекта) сам вычисляет следующий шаг, агента и модель.
4. Независимый инспектор заново прогоняет проверки. PASS журнал принимает, только если каждая обязательная проверка дала OK в этом же прогоне; «не запускалась», «пропущена» и «не прошла» одинаково блокируют.
5. Перед дорогим рендером вы утверждаете лист предпросмотра.
6. После закрытия каждое ваше замечание записывается с причиной: `agent` (критерий был, но не выполнен), `brief` (в брифе этого не было), `taste` (новое пожелание). Замечание становится новым изделием, а дефект — новой проверкой.

Рабочая сцена, утверждённая библиотека материалов и исходный проект Archicad не изменяются: работа идёт на копиях.

## Этапы нового проекта

| Этап | Что проверяется скриптами |
|---|---|
| `export` — модель из Archicad | масштаб по эталонному объекту, положение, идентификаторы элементов, имена покрытий, дубликаты, размер |
| `environment` — существующее окружение | ступень и зазор на стыке с моделью участка, дыры рельефа, текстуры |
| `materials` — материалы покрытий | совпадение с утверждённой библиотекой, UV, реальный размер текстуры |
| `cameras` — камеры и облёт | наличие, объект в кадре, отсечение, объективы, равномерность кольца облёта |
| `render-setup` — настройки рендера | настройки по списку, солнце по месту, дате и часу |
| `render`, `pack` | число, размер и вес кадров, чёрные, пересвеченные, повторные и пропущенные кадры, шов облёта |

После изменения модели: `swap` (новая модель, те же материалы, камеры и солнце) → `env-adjust` (окружение меняется только внутри заданной зоны) → `render` → `pack`. Отдельно: `audit` (только чтение) и `fix` (дефекты).

Критерии каждого этапа, пригодные для любого способа связи Archicad и Blender, — в `skills/viz-item/scripts/STAGES.md`. Формат брифа с примером — в `skills/viz-item/references/brief.md`.

## Агенты

| Агент | Модель | Что делает |
|---|---|---|
| `viz-conductor` | Haiku | бриф; все вопросы задаёт сразу, одним списком, до начала работы |
| `scene-cartographer` | Haiku | только чтение: цифры и дефекты сцены |
| `scene-operator` | Haiku | запускает зарегистрированные скрипты пакетами |
| `scene-builder` | Sonnet | пишет скрипт этапа, когда готового нет, и регистрирует его; дальше этап выполняет оператор на Haiku |
| `viz-inspector` | Sonnet (Haiku для проверок по цифрам) | независимая проверка, запись результатов, вердикт |

Модель повышается на одну ступень после двух неудач шага и возвращается после успеха.

## Как понять качество работы агентов

`vizflow.py quality` показывает раздельно:
- **агентов** — по каждой паре «агент + модель»: в скольких изделиях работу вернул инспектор, и вывод: надёжен, наблюдать, поднять модель или «мало данных» (меньше 5 изделий);
- **инспектора** — в скольких принятых им изделиях вы потом нашли дефект;
- **брифы** — сколько замечаний вызвано отсутствующим критерием и сколько брифов менялось после утверждения;
- обходы (снятые проверки, принудительные шаги), число кругов предпросмотра и расход токенов по моделям.

## Скрипты

Все скрипты написаны для этого метода, сторонние наборы blender-skills не используются. `blender/selftest_blender.py` строит маленькую сцену в отдельном фоновом Blender и требует, чтобы каждая проверка прошла там, где должна, и не прошла там, где не должна:

```
blender --background --factory-startup --python _viz/tools/blender/selftest_blender.py
```

Тесты без Blender: `python3 -m unittest discover -s tests`.

## Запуск

Скажите «выполни задачу viz-flow: …» или вызовите `/viz-item`.
